# Auto Post

## Overview

Auto Post is a multi-platform social media post generator. It is **not** LinkedIn-only: a user picks a platform, connects their account, provides a prompt (and optionally an image, or an MP4 video for LinkedIn), gets a post generated by Google Gemini, previews it, and publishes it directly to that platform.

Supported destinations:

- **LinkedIn** — fully working (OAuth login + publish).
- **Instagram** — 90% finished, currently with an internal related to the access of the business account of Facebook/Instagram that is needed for the integration of Facebook api
- **TikTok** — shown in the platform selector as "Coming soon"; not implemented yet.

The app is split into:

- `client/`: React + Vite frontend
- `server/`: Node.js + Express backend, deployed to Vercel as serverless functions

Both are separate npm workspaces under the root `package.json`.

## Current flow

1. The user lands on a scrollable marketing page (hero + "why Auto Post" + "how it works" sections) that ends in a "Create. Publish." call-to-action.
2. The user picks a platform from a card-based selector (LinkedIn or Instagram today).
3. Picking a platform redirects the user through that platform's OAuth login. A connected session can be ended again from the UI, which clears the session cookie via a logout endpoint.
4. On successful login, the user is dropped into the create screen: upload an optional image (or, for LinkedIn, an MP4 video), write a prompt/context.
5. If the selected file is a video, the frontend uploads it directly to Vercel Blob from the browser (using a short-lived, scope-limited client token issued by the backend), bypassing the serverless function's request body size limit — otherwise, the selected image is converted to base64. Either the resulting video URL or the base64 image, together with the prompt, is sent to the backend.
6. The backend validates the request (`createPostValidator`) and calls `generatePost` from `gemini.service.js`.
7. Gemini generates platform-ready post text from the prompt (and image, if provided).
8. The frontend shows a loading overlay while generation is in progress, then a preview overlay with the generated text and image or video.
9. The user publishes directly from the preview overlay:
   - LinkedIn: an image or video (if any) is registered and uploaded via LinkedIn's classic assets API, then a UGC post is created. If a video was used, the temporary Blob copy is deleted once LinkedIn has ingested it.
   - Instagram: requires an image (Instagram's API doesn't support text-only posts). The generated image is temporarily hosted on Vercel Blob so Instagram's Graph API can fetch it, then published as a media container.

## Technologies used

- React 19 + Vite (frontend)
- Node.js + Express (backend)
- MongoDB / Mongoose (connected, not yet used to persist posts — see [Current status](#current-status))
- Joi (request validation)
- Google Gemini via `@google/genai` (post generation)
- LinkedIn OAuth 2.0
- Instagram Graph API via Facebook Login OAuth
- Vercel Blob (temporary public media hosting: images for Instagram publishing, and browser-direct video uploads for LinkedIn video posts)
- Deployed on Vercel (client and server as two separate projects; the server runs as serverless functions)

#### `client/src/`

- `styles.css`: global styles for the app, overlays, and every view

### `server/`

Backend application built with Express, deployed to Vercel as serverless functions.

- `server/package.json`: backend dependencies and scripts
- `server/vercel.json`: rewrites every request to the single serverless entrypoint
- `server/api/index.js`: Vercel serverless entrypoint — imports and re-exports the Express app
- `server/src/app.js`: the actual Express app (CORS, JSON body parsing, routes, lazy Mongo connection). No `.listen()` here.
- `server/src/server.js`: local-dev-only entrypoint — imports `app.js` and calls `.listen()`

#### `server/src/routes/`

- `auth.routes.js`: LinkedIn + Instagram OAuth and logout endpoints
- `post.routes.js`: post generation, publish, and media-upload-token endpoints

#### `server/src/controllers/`

- `authController.js`: LinkedIn and Instagram login/callback/me/logout handlers
- `postController.js`: validates requests, calls the post service, returns generated/published posts; also issues short-lived Vercel Blob client tokens for direct browser-to-Blob video uploads

#### `server/src/services/`

- `gemini/gemini.service.js`: sends prompt + image to Gemini, returns generated post text
- `linkedin/auth/linkedinAuth.service.js`: LinkedIn OAuth login/callback/session/logout handling
- `linkedin/post/linkedinPost.service.js`: registers + uploads image or video assets (against LinkedIn's classic assets API, the only product this app is approved for) and creates the LinkedIn UGC post
- `meta/instagram/auth/instagramAuth.service.js`: Instagram OAuth via Facebook Login — token exchange, resolves the Facebook Page and its linked Instagram professional account
- `meta/instagram/post/instagramPost.service.js`: creates and publishes the Instagram media container
- `post/post.service.js`: platform-agnostic orchestration — builds the generated `Post`, delegates publishing to the LinkedIn/Instagram services, cleans up the temporary LinkedIn video Blob after publish
- `post/imageHost.service.js`: uploads a generated image to Vercel Blob so Instagram can fetch it, and shares the Blob delete helper used to clean up both Instagram images and LinkedIn videos

#### `server/src/models/` and `server/src/mongoose/schemas/`

- `models/Post.js`, `models/User.js`: plain domain classes used to shape objects through the current flow (`Post` carries an optional `imageUrl` or `videoUrl`)
- `mongoose/schemas/post.schema.js`, `mongoose/schemas/user.schema.js`: Mongoose models — defined and connected, but **not yet called** anywhere (no `.save()` in the codebase). Persistence is not part of the working flow yet.

#### `server/src/validators/`

- `createPostValidator.js`: validates prompt, author, and optional image (URL, base64, MIME type, file name) or video URL

#### `server/src/errors/`

- `PostError.js`, `UserError.js`: domain-specific error classes

#### `server/src/utils/`

- `cookies.js`: shared cookie build/parse helpers used by both the LinkedIn and Instagram auth services

## Backend behavior

### Post generation

- `POST /api/posts/create`

Expected request payload:

```json
{
  "title": "Short title",
  "content": "Prompt or context written by the user",
  "authorUsername": "linkedin-user",
  "imageBase64": "base64-encoded-image",
  "imageMimeType": "image/png",
  "imageName": "logo.png",
  "videoUrl": "https://.../linkedin-uploads/video.mp4"
}
```

`imageBase64`/`imageMimeType`/`imageName` and `videoUrl` are mutually exclusive — a video is uploaded straight to Vercel Blob from the browser first (see `POST /api/posts/media/upload-url` below), and its URL is sent here instead of raw video bytes.

What the backend does:

- validates the payload with Joi
- calls Gemini with the user prompt (and image, if provided)
- returns a `Post` object with the generated text in `content`
- builds `imageUrl` as a data URL when the image came from base64 input; passes `videoUrl` through unchanged

### Media upload token

- `POST /api/posts/media/upload-url` — requires an active LinkedIn session; issues a short-lived, scope-limited Vercel Blob client token (MP4 only, up to 500MB) so the browser can upload a video directly to Blob storage, bypassing the serverless function's request body size limit

### Publishing

- `POST /api/posts/publish` — publishes to LinkedIn (requires an active LinkedIn session). Supports an image or a video (`videoUrl` from the upload step above); the temporary video Blob is deleted after LinkedIn has ingested it.
- `POST /api/posts/publish/instagram` — publishes to Instagram (requires an active Instagram session and an image on the post)

### LinkedIn auth

- `GET /api/auth/linkedin`
- `GET /api/auth/linkedin/callback`
- `GET /api/auth/linkedin/me`
- `POST /api/auth/linkedin/logout`

### Instagram auth

- `GET /api/auth/instagram`
- `GET /api/auth/instagram/callback`
- `GET /api/auth/instagram/me`
- `POST /api/auth/instagram/logout`

Both auth flows redirect the browser to the provider, then redirect back to the frontend with `?linkedin=ok|error` or `?instagram=ok|error` query params, which the frontend consumes and strips from the URL.

## Environment variables

The backend reads environment variables from `server/.env` locally, and from the Vercel project's Environment Variables in production.

```env
MONGODB_URI=your_mongodb_connection_string
FRONTEND_URL=http://localhost:5173

LINKEDIN_CLIENT_ID=your_linkedin_client_id
LINKEDIN_CLIENT_SECRET=your_linkedin_client_secret
LINKEDIN_REDIRECT_URI=http://localhost:3000/api/auth/linkedin/callback

META_APP_ID=your_facebook_app_id
META_APP_SECRET=your_facebook_app_secret
INSTAGRAM_REDIRECT_URI=http://localhost:3000/api/auth/instagram/callback

GEMINI_API_KEY=your_gemini_api_key

BLOB_READ_WRITE_TOKEN=your_vercel_blob_token
```

The frontend reads `VITE_API_BASE_URL` (build-time Vite env var) pointing at the backend's base URL.

Notes:

- `GEMINI_API_KEY` is required for post generation.
- `FRONTEND_URL` is used by the backend CORS configuration and to build OAuth redirect URLs back to the client.
- Instagram auth uses `META_APP_ID` / `META_APP_SECRET` (Facebook Login), not a separate Instagram app — `INSTAGRAM_APP_ID` / `INSTAGRAM_SECRET`, if present in an older `.env`, are unused by the current code.
- `BLOB_READ_WRITE_TOKEN` is required for Instagram publishing (temporary image hosting) and for LinkedIn video posts (issuing scoped client tokens for direct browser-to-Blob video uploads); connect a Blob store to the Vercel server project to get it injected automatically in production.
- The redirect URIs registered in the LinkedIn Developer Portal and the Meta App dashboard must exactly match `LINKEDIN_REDIRECT_URI` / `INSTAGRAM_REDIRECT_URI`.
- Avoid spaces around `=` in `.env` entries.

## Running the project

Install dependencies (installs both workspaces from the root):

```bash
npm install
```

Start the backend:

```bash
npm run dev
```

Start the frontend:

```bash
npm run client:dev
```

Build the frontend:

```bash
npm run client:build
```

## Deployment

The client and server deploy as two separate Vercel projects from this same repository:

- **Client project** — Root Directory `client`, framework auto-detected as Vite.
- **Server project** — Root Directory `server`. `server/vercel.json` rewrites every request to `server/api/index.js`, which runs the Express app (`server/src/app.js`) as a serverless function. Needs a Blob store connected for Instagram publishing.

Both projects need their own environment variables set (see above) — the redirect URIs in particular must point at the deployed server's domain, not `localhost`.

## Summary

Auto Post is a working multi-platform content generator: a user picks LinkedIn or Instagram, authenticates, provides a prompt and optional image (or, for LinkedIn, an MP4 video), generates a post with Gemini, previews it, and publishes it directly to the connected account.
